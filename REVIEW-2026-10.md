# REVIEW — security, consistency, and what to build next (2026-10-12)

Every finding was read in the source; those marked **[reproduced]** were reproduced against the real
endpoints with the repo's own harness (`tests/php/php.mjs`, php-wasm + PHP 8.4), with the command and
the output inline so they can be re-run.

Severity: **P0** fix before the next deploy · **P1** this sprint · **P2** backlog.

What is already solid, because it shapes the advice: prepared statements throughout
(`cdr_store.php`), no `eval`/`unserialize`/dynamic include anywhere, domain-scoped cache keys, a real
SSRF allowlist with per-hop revalidation and token stripping (`includes/security.php`), CSV formula
neutralisation, SRI on every third-party byte, a server-side metric catalog,
`session_regenerate_id()` on login, and a 29-suite gate in `npm test`. The gaps below are gaps in a
codebase that takes these things seriously — not the absence of the practices.

---

## 1. Security

### S1 — P0 — the CDR cache and the audit trail are inside the web root, with no protection

`includes/config.php` puts runtime state under the app root:

```
CACHE_DIR = APP_ROOT . '/cache'      LOG_DIR = APP_ROOT . '/logs'
```

`includes/bootstrap.php` creates both on the first request, and the README deploy step is
"copy `*.php`, `api/`, `includes/`, `assets/` … to the web root". So in the documented shape of a
deployment, `https://host/cache/…` and `https://host/logs/…` are static files served by the same
web server, and **there is no `.htaccess` anywhere in this repository** (`find . -name .htaccess`
→ nothing) and no guard in the PHP.

The filenames are hashes, not secrets. `includes/reporting/inventory.php:12`:

```php
$file = CACHE_DIR . '/users-' . hash('sha256', 'v3|' . $user['domain']) . '.json';
```

`$user['domain']` is the tenant's own domain name — public, and guessable from the login page or
an email address. The file it names is the **raw PBX roster** (`(new PbxClient(...)->users($domain)`,
written straight through): every extension, first/last name, department, site and `login-username`.

**[reproduced]** the URL is fully predictable — for tenant `acme.example`:

```
node -e "const c=require('crypto');const h=s=>c.createHash('sha256').update(s).digest('hex');
  console.log('users-'+h('v3|acme.example')+'.json');"
→ users-2c4f53be9eaf127898b6abc01cf9239726b6474b768aed337609d406b2bd6a7c.json
```

Same pattern, same reachability, for the rest of the cache:

| file | key | what it contains |
| --- | --- | --- |
| `users-*.json` | `v3\|<domain>` | full staff roster + login usernames |
| `cdr-day-*.json` | `v7\|<domain>\|<day>\|<PBX host names>` | **caller phone numbers, caller-ID names, every leg of every call** |
| `settings-*.json` | `v1\|<domain>` | the tenant's SLA/calendar/roster config |
| `callqueues-*.json`, `callqueue-agents-*.json` | `v1\|<domain>` | queue inventory and their members |
| `logs/app-*.log` | none | refused URLs, absolute filesystem paths, usernames, error details |
| `logs/audit-*.jsonl` | none | **who** looked at **which** numbers, with filters — 12 `auditView()` call sites |

The CDR day files are the worst of them: `cdr-day-…json` needs the PBX host list in the key
(`implode(',', array_keys(PBX_SERVERS))`), and in practice that is `nms1,nms2`.

Fix, in the order that costs least:

1. **Move the defaults out of the doc root.** `CACHE_DIR`/`LOG_DIR` already read from
   `config.local.php`/env — change the *default* to `APP_ROOT . '/../callscope-cache'` and
   `…/../callscope-logs`, and make `deploy-check` fail if the resolved path is under the document
   root. Existing installs keep working by setting the constant.
2. **Ship the deny rules anyway** (defence in depth for shared hosts where the app must live in
   the doc root): `cache/.htaccess` and `logs/.htaccess` with `Require all denied`
   (+ `Order deny,allow / Deny from all` for Apache 2.2), written by `bootstrap.php` when it
   creates the directory, and a `nginx.conf` snippet in the README.
3. **Make `tools/deploy-check.mjs` assert it.** It already fetches every deployed file and
   compares bytes; add a check that `GET <base>/logs/` and
   `GET <base>/cache/<the-hash-the-tool-can-compute-from-the-tenant-domain>` are 403/404, and exit
   1 otherwise. That turns a silent exposure into a failed deploy, which is how this repo handles
   every other class of deploy mistake (QA-3, QA-4).
4. Add an `index.php`-style empty file in each directory (cheap, does not substitute for 1–3), and
   stop writing absolute paths into the log (`inventory.php:15` logs `{$file}`).

Related, same area: **no log rotation or retention.** `app-*.log` and `audit-*.jsonl` grow one
line per request forever (`cache.php` prunes cache days; nothing prunes logs). A
`tools/` CLI + a retention setting (`LOG_RETENTION_DAYS`, default 180) closes it.

### S2 — P1 — the recording proxy serves whatever Content-Type the upstream chose, inline, from our origin

`api/recording.php:159-162`:

```php
$type = $file['contentType'];
if ($type === '' || str_contains(strtolower($type), 'json') || str_contains(strtolower($type), 'text/html')) {
    $type = 'audio/mpeg';
}
header('Content-Type: ' . $type);
```

`$file['contentType']` is `CURLINFO_CONTENT_TYPE` from the upstream response
(`includes/PbxClient.php:1552`). The block is `GET /api/recording.php?stream=1&src=<url>`, so the
bytes land in the browser **same-origin** with the victim's session context. `text/html` is
blocked, but `image/svg+xml` and `application/xhtml+xml` are not, and there is no
`X-Content-Type-Options: nosniff` and no `Content-Disposition` on that response — so an
allowlisted host that returns (or is made to return) an SVG with `<script>` executes in the app
origin. The URL policy permits any `*.parent-domain` of a configured PBX host
(`pbxParentDomain()`, `security.php`), i.e. any subdomain of the PBX's domain, not only the tenant's.

Fix (3 lines, and it kills the whole class rather than this instance):

```php
$allowed = ['audio/mpeg','audio/mp3','audio/wav','audio/x-wav','audio/ogg','audio/aac','audio/mp4'];
$type = in_array(strtolower(strstr($type . ';', ';', true)), $allowed, true) ? $matched : 'application/octet-stream';
header('X-Content-Type-Options: nosniff');
header('Content-Disposition: inline; filename="call-' . $safeId . '.audio"');
header('Content-Security-Policy: default-src \'none\'; media-src \'self\'');
```

`<audio>` does not need a rich MIME type to play, so an allowlist costs nothing here.

### S3 — P1 — the recording download has no size cap: one upstream response can exhaust PHP memory

`PbxClient::fetchUrl()` uses `CURLOPT_RETURNTRANSFER` with no `CURLOPT_MAXFILESIZE` and no
write callback (`includes/PbxClient.php:1528-1583`), timeout 60 s, and the result is buffered
again for `strlen($file['body'])` + `echo` in `recording.php:157-165`. The app's own fatal handler
exists precisely because `memory_limit` exhaustion happened in production
(`bootstrap.php:installApiFatalHandler`), and that handler is what this would hit.

Fix: `CURLOPT_BUFFERSIZE`+`CURLOPT_WRITEFUNCTION` streaming to `php://output` with a byte counter
that aborts at, say, `RECORDING_MAX_BYTES` (default 100 MB), or the one-liner
`CURLOPT_MAXFILESIZE`. Streaming also removes the "play a 40-minute call → 2× its size in RAM"
case that the current design has regardless of any attacker.

### S4 — P1 — sign-in has no throttle, and usernames can forge log lines

`api/login.php` forwards every attempt to the PBX and, on failure:

```php
appLog("Login failed for {$username}: HTTP {$status}");
```

* Nothing rate-limits or back-offs failed attempts in this app (the PBX may, but the dashboard is
  also the thing an attacker sees, and each attempt is an outbound curl + full PHP bootstrap).
* `$username` is only `trim()`-ed, so an embedded `\n` writes attacker-controlled lines into
  `logs/app-*.log` — and those lines are the evidence trail. Same class at
  `recording.php:100,129` (`appLog('Recording refused src: ' . substr($src, 0, 200))`, where
  `$src` comes from `$_GET`), and `inventory.php:15`.

Fix: one sanitizer used by `appLog()` itself, not at each call site:

```php
function logSafe(string $s): string {
    $s = preg_replace('/[\x00-\x1F\x7F]/', ' ', $s) ?? '';   // no CR/LF/TAB, ever
    return substr(trim($s), 0, 300);
}
```

plus a per-session/per-IP failed-login counter (the file-based limiter in `PbxClient::rateLimit()`
is already there as a pattern to copy) that returns 429 with a `Retry-After`.

### S5 — P2 — no security headers on the HTML shell, and `cookie_secure` is guessed

`grep -rn "Content-Security-Policy|X-Frame-Options|Referrer-Policy|Strict-Transport" api/ includes/`
→ only `export.php`'s `nosniff`. `portal.php` renders the app; every API response is JSON.

* `X-Frame-Options: DENY` / `Content-Security-Policy: frame-ancestors 'none'` — the dashboard is
  a click-jackable list of caller numbers.
* `Referrer-Policy: same-origin` — `?start=&end=&department=` travel in the URL
  (`app-shell.js:36-48`) and would otherwise leak a tenant/domain to any external link.
* CSP: `default-src 'self'`; the app is already CDN-free and SRI-pinned so `script-src 'self'` is
  free. `style-src` needs `'unsafe-inline'` today (inline `style=` attributes are used heavily in
  the charts/bars) — worth stating in the header comment so nobody thinks it was overlooked.
  This is the belt to the Tabulator-`innerHTML` braces (`asText`, SEC-9): the JS formatters that
  return *strings* are applied with `innerHTML`, and `slaRingHtml()` (`lib/sla.js:31-36`) is still
  one — safe only because it interpolates `fmt(Number(...))` and a fixed class name. Make it
  return a node like its neighbours, or leave a comment there, because the next edit to that
  function may not be number-only.
* `bootstrap.php:16` — `cookie_secure' => !empty($_SERVER['HTTPS'])`. Behind a TLS-terminating
  proxy (the normal shape) `$_SERVER['HTTPS']` is empty, so the session cookie is issued without
  `Secure` even though users reach the app over https. Read `X-Forwarded-Proto` (and add
  `FORWARDED_ALLOWED=1`-style config so a spoofed header on a non-proxied host cannot downgrade
  the flag… the real rule: trust the header only if a trusted-proxy constant is set).

### S6 — P2 — `cache_job.php` is reachable by every role and costs PBX fetches

`api/cache_job.php` has `currentUser()` but no `requirePageRoles()`, and `action=warm` runs
`warmCdrBatch(..., 5 days, 20 s)` with `set_time_limit(120)` — five full-day CDR fetches per
request, for the whole domain, regardless of the caller's row scope. The role matrix
(`tests/php/endpoints.mjs`) records this deliberately (`forbidden: []`), so it is a decision, not
an oversight — but it is the one endpoint where an `agent` role can make the *shared* cache and the
PBX do work, repeatedly, and it is not covered by the per-IP limiter. Recommend `requirePageRoles`
`['office_manager','supervisor']` for `action=warm` (leave `status` open so the warming bar keeps
working for agents), or a per-user warm budget.

### S7 — P2 — role scoping fails open when the PBX omits `department`

`includes/auth.php:authorizedFilters()` pins a supervisor to
`$result['department'] = (string)($user['department'] ?? '')`, and `includes/reporting/rows.php:144`
applies it only when non-empty:

```php
if ($filters['department'] !== '' && $department !== $filters['department']) return false;
```

A supervisor whose token carries no department therefore sees the whole tenant (the same row set as
an office manager, minus the manager-only endpoints). Agents are still pinned by
`agents => [own extension]`, so the exposure is supervisor-or-above. If any real tenant has
department-less supervisors this is P1, not P2 — worth one question to ops, then either
"supervisor with empty department → no access to cross-department views" (fail closed) or an
explicit, documented allowance.

Also worth adding to that block: a supervisor's `site` is taken from the request verbatim
(`$result['site'] = trim((string)($requested['site'] ?? ''))`) and `agents` is an unvalidated list of
strings. Both are ANDed against the department, so neither escapes the tenant — but validating
`site`/`agents` against `userDirectory()` would make the scope rule readable instead of emergent.

### S8 — P2 — no Origin check on state-changing POSTs (currently mitigated, don't lose the mitigation)

Every endpoint except the recording stream requires POST, the session cookie is
`SameSite=Lax`, and CSRF is therefore effectively dead today. That safety rests on an invariant
nobody is enforcing. Two cheap guards: reject a request whose `Origin` header is present and
differs from `Host`, and add `tests/php/security.mjs` a case "no endpoint that writes state accepts
GET" (recording.php's `?stream=1` GET is the one deliberate exception — worth naming in the test
so a future GET-with-side-effect fails the gate).

### S9 — P2 — small ones

* `index.php` is `require_once 'portal.php'` — a relative include, the only one in the codebase.
  It works because '.' is normally in `include_path`; on a host where it isn't, `/` 500s while
  `/portal.php` works, which is a confusing way to fail. `require_once __DIR__ . '/portal.php';`
* `cache/*.json` is written with `@file_put_contents` — the `@` means a permissions failure is
  silently tolerated (and the fallback is a full PBX refetch on *every* request). Log it once per
  directory, not per request.
* `PBX_SIP_TOKEN`, `PBX_CLIENT_SECRET`: fine in env. Add to `deploy-check` a probe that
  `GET /includes/config.local.example.php` returns nothing useful and that
  `GET /.gitattributes`, `GET /CHANGES.md` (which quotes internal host names and log excerpts) are
  not served — `CHANGES.md` is in the README's *copy list*, so it currently is.
* `readJsonBody()` has no size cap: a 200 MB JSON body is parsed into memory before any filter is
  read. `if ($_SERVER['CONTENT_LENGTH'] > 65536) → 413` in `bootstrap.php` closes it.

## 2. Consistency

### C1 — P0 **[reproduced]** — the sentiment filter re-scopes every Dashboard number, and is silently ignored by every drill-down behind them

`filterCallsBySentiment()` is called by **one** endpoint:

```
$ for fn in filterCallsByOutcome filterCallsByWait filterCallsBySentiment filterCallsByCallback; do …; done
filterCallsBySentiment   api/report.php includes/reporting/rows.php     # ← no api/calls.php
```

`api/calls.php` has zero references to `sentiment`, while `assets/js/src/components/call-modal.js:115`
sends `...filters` (which includes it) and `filters.js:440` offers it as a *global* select. So with
"Negative only" active, every KPI/card is computed over negative-sentiment calls, and the list that
opens when you click one of them is unscoped — the README's stated promise ("every figure that opens
a call list sends the filters that figure was computed with, so the list adds up to the number that
was clicked") is broken for exactly this one control.

**[reproduced]** with the harness, fixture of 2 abandons (one returned), the same day:

```
sentiment=negative   card: missed=0 returned=0 unreturned=0  |  modal rows=[w6,w5]  ← list shows calls the card cannot see
```

Fix: apply `filterCallsBySentiment($calls, $requested['sentiment'])` in `calls.php` at the same
point the other narrowing filters are applied (`api/calls.php:~650`, next to
`filterCallsByOutcome`), and add it to the CSV path. Then close the class with C9.

### C2 — P1 **[reproduced]** — the Follow-ups card recomputes its own answer under a narrowing filter, and disagrees with its list

`api/report.php:282` computes `callLinkReport($calls, …)` **after** the outcome/wait/sentiment/
callback narrowing filters (lines 171-211), i.e. over whatever is left of the day. `api/calls.php`
deliberately computes its callback sets **before** narrowing (its "PER-ROW CONTEXT" block documents
why). The two ends of one drill therefore use two different row sets, and the disagreement has a
direction: drop the outbound legs and every returned miss becomes "not returned".

**[reproduced]** same fixture, `outcome=abandoned` in the global filter bar:

```
no filter            card: missed=2 returned=1 unreturned=1  |  not-returned drill=[w6]   ✓
outcome=abandoned    card: missed=2 returned=0 unreturned=2  |  not-returned drill=[w6]   ✗ card 2, list 1
```

Fix: compute `callLinkReport()` in `report.php` from the scope-filtered set (start/end/department/
site/agents/hours/types) and before the list-narrowing filters, exactly like `calls.php` does.
"Just was this customer called back" is a property of the period, not of the subset someone happens
to be viewing; the `callbackWindow`/`$queueIds` arguments then also match between the two ends.

### C3 — P1 **[reproduced]** — "offered" and "missed" silently mean rows in one card and interactions in another

`summary()` counts rows: `includes/reporting/rows.php:373` `$offered = $counts['inbound'] + $counts['missed']`.
The links layer counts *conversations*: `links.offered = count(cdrOfferedInteractions($calls))`
(deduped by root, `links.php`), and `cdrCallbacks()`' `counts.missed` is "missed **interactions with a
matchable customer number**" — a third denominator again.

**[reproduced]** one 2-leg missed conversation, one blocked-number miss, one answered call:

```
summary.counts        {"total":4,"inbound":1,"outbound":0,"missed":3,"onnet":0}
links.offered         3                     ← interactions
summary.missedBreakdown {"abandon":3}       ← rows
links.callbacks       {"missed":1,"returned":0,"unreturned":1,"ratePct":0}
```

So the Dashboard can print "Missed 3" beside "0% of 1 were returned" and neither number says what
it counted. A 2-leg missed call also *lists* as two rows under a card that counted one.

Fix (cheap, and it removes a whole support-question category):
1. put the unit in the payload and in the label: `'unit' => 'interaction'` next to every links
   count, and render "1 conversation nobody called back (of 3 missed calls)" rather than bare
   numbers;
2. make `cdrCallbacks()` disclose the misses it *could not* match instead of dropping them
   (`'unmatchable' => 1` — blocked/private/short numbers), so `ratePct`'s denominator is auditable;
3. one definition of "offered" per screen, chosen in code, not per consumer.

### C4 — P1 **[reproduced]** — the queue↔queue transfer insight is computed and never delivered

`callLinkReport(array $calls, array $directory = [], array $queueIds = [], …)` is called from
exactly one place, `api/report.php:282`, with `$queueIds` omitted — while `$queueIds` is in scope
two lines away and is passed to `summary()` (`:234`), `filterCallsByOutcome()` (`:171`) and the
packs (`:530`). With no queue ids, `cdrHopSequence()` leaves every hop's `queue` empty and
`transfers.queuePairs` is always `[]`:

```
as report.php calls it : agentPairs [6080→6081 ×1]  queuePairs []
with queueIds passed   : agentPairs [6080→6081 ×1]  queuePairs [700→701 ×1]
```

And `grep queuePairs assets/js/src` shows the UI never renders it either — so the field is dead
payload in both directions. Fix: pass `$queueIds` and render "Sales → Support ×12" under the
transfer row (it answers "which two desks keep bouncing people"), or delete the field.

### C5 — P1 — `api/queue.php` and `api/cradle.php` are 89% the same file, and they already disagree

```
overall similarity: 0.89   — 500 identical lines in 10 copy-pasted blocks
```

The divergence is not cosmetic:

| | `queue.php` | `cradle.php` |
| --- | --- | --- |
| which rows belong to a queue | `cdrQueueMatch($row, $queueIds)` (shared matcher: batch legs, AA/IVR signals) | `$extractExt($row['call-through-user'])` + `isset($queueIds[…])` |
| which rows are one conversation | own union-find + `$relatedCdrs($row)` closure | `findRelatedCdrs($raw, $row)` (`rows.php:1226`), differently typed `$ufFind` |
| hold time | not tracked | `holdSum/holdN/holdAvg/holdTotal` |
| longest wait / longest talk | `waitMax`, `talkMax` | not tracked |
| SLA per queue | `$targetFor()` | `$queueTarget()` |
| `perQueueTargets` | `$queueSlaMap !== []` | `is_array(…) && … !== []` |

The first row is a **number-changing** difference: a queue call recorded only on a batch leg, or
routed via the auto attendant, counts on the Queues screen and not on the Cradle screen (and the
README's "one definition" promise is made about `outcomes.php`, which covers answered/abandoned —
not queue membership or leg grouping). This is exactly how the callback bug in the last change
lived: one side of a pair was patched in one file.

Fix: extract the shared pipeline into `includes/reporting/queues.php` (the repo already does this
mechanical split for `cradle.php`, `pack.php`, `inventory.php`) with one function each for
`queueMembershipOf($row, $queueIds)`, `interactionGroups($raw)` (→ reuse `cdrLegIndex()`), and the
per-queue accumulator; keep the two endpoints as thin view shapers. Then `tests/php/outcomes.mjs`
can assert "queue 700's numbers agree between the two screens" instead of people noticing.

### C6 — P2 — three definitions of "is this the same call"

`cdrLegIndex()`/`cdrRootKey()`/`cdrInteractionLegs()` in `links.php` (the good one, and what the
callback fix uses), `queue.php`'s inline union-find over `cdrIdBag()`, and `findRelatedCdrs()` +
`groupRelatedCdrs()` in `rows.php:1226`. Three rules for "same conversation" means three answers to
"how many calls is this?". Same class as C5: converge on the links layer's index and note in
`links.php` that it is the only grouping rule.

### C7 — P2 — the desk's timezone is a compile-time constant, and two endpoints let the caller pick their own

`DEFAULT_TIMEZONE` (`config.php`, default `'US/Eastern'`) drives every day boundary, hour-of-day
chart, business-hours filter and `easternDayWindow()`. It is per-deployment only — the app is
multi-tenant by `domain` and stores per-domain SLA, calendar and holidays in
`settings-<domain>.json`, but **not** the timezone. A second tenant in another timezone is
mis-dated by hours, and a manager travelling (or a browser) in another zone sees a different
"Today" than the server: `assets/js/src/lib/time.js:40` is `const today = date(new Date())` —
browser-local.

Meanwhile `api/simultaneous_calls.php:91` and `api/telephone_numbers.php:76` accept
`$input['timezone']` from the client (validated by `new DateTimeZone` + fallback, so safe — but
it means two screens bucket by a caller-chosen clock while the Dashboard buckets by the server's).

Fix: `timezone` as a domain setting (defaulting to `DEFAULT_TIMEZONE`), passed to
`reportingTimezone()`/`easternDayWindow()` — which is already exactly how `slaSeconds` and the
business-hours calendar work — and have `today`/`yesterday` come from the server
(`report.php` already returns `'timezone' => DEFAULT_TIMEZONE`); either drop the client-supplied
`timezone` on those two endpoints or send it from the same single place everywhere. Rename the
`US/Eastern` legacy alias to `America/New_York` for consistency with the fallback in
`support.php:14`.

### C8 — P2 — per-agent rates are computed on both sides

`rows.php:1160-1172` publishes `offered`, `mcRate`, `abRate` for the Agents table, and
`assets/js/src/components/agent-table.js:85-86` recomputes both client-side
(`(mc + ab) / off * 100`, unrounded) while other screens read the server's rounded values. The
formula happens to agree today (including the subtle fact that `mc` excludes abandons, which is why
`mc + ab` is not a double count). Either render the server value everywhere, or delete
`mcRate`/`abRate` from the payload — do not keep two.

Related: `api/agents.php:44` still contains a debug line that runs on every request —
`appLog('AGENTS DEBUG: cachedUsers count = ' . count($users));`. Delete it (it also puts tenant
head-count in the log that S1 exposes).

### C9 — P1 — make filter parity a gate, so C1/C2 cannot come back

The root cause of C1 and C2 is that a filter is *added to the UI + one endpoint* and nothing
notices. The repo already has the pieces of a gate:

* `includes/reporting/metrics.php` is the one catalog for drill-down metric ids, and
  `api/filters.php` hands it to the client so nobody re-types labels (QA-8). Do the same for
  **filters**: a `callFilters()` catalog in `rows.php` — key, type, validator, and
  `apply(array $calls, $requested, $context): array` — with `report.php`, `calls.php`,
  `call_history.php`, `queue.php` and `cradle.php` all looping over the same list.
* A test that reads the catalog and asserts, per filter key, that `report.php`'s `summary` and
  `calls.php`'s row set shrink **by the same amount** for the same value — the existing
  "drill parity" checks in `tests/php/call-links.mjs` already do this for wait buckets and the
  callback states; generalise that block to the catalog and every future filter is covered the day
  it is added.
* `app-shell.js:86-99` already builds `filtersKey` from an explicit list. Have the client send
  the whole `filters` object and let the server echo back `appliedFilters`; the modal then renders
  chips from the *server's* answer instead of its own guess — and a filter the server ignores
  becomes visible instead of silently absent.
* `filtersKey` contains `callbackState`, which no UI control sets (`grep callbackState` in
  `filters.js` → nothing). Dead key: delete it or finish the control.
* Tests pass `perPage: 100` to `calls.php`, which reads `size` (clamped 10..100) — the param is
  ignored and those assertions silently assume "≤25 rows". Use `size`, or the day a fixture grows
  past 25 rows the tests change meaning without failing loudly.

### C10 — P2 — vocabulary and wording

* "Missed" means *not answered* in `outcomes.php` (abandoned included) and *type `missed`* in
  `callType()`; the modal's `metric=missed` filter and the Missed KPI are therefore not the same
  population for calls the PBX typed differently. It is documented in the README — the fix is to
  say it in the payload too (`'definition' => 'outcomes.php: unanswered'`) and let tooltips read it
  from there, so docs and UI can't drift.
* `metrics.php` labels are re-typed in `call-modal.js` chips (`returned` → "not returned",
  `120+` → "over 120s", `31-60` → "31–60s"). One label map, served with the catalog.
* En-dash vs hyphen in published ranges (`0-30` in code, `0–30` in UI) is fine, but
  `filterCallsByWait`'s bands (`0-30,31-60,61-120,120+`) are *not* the same bands as
  `missedWaitBuckets`/`abandonWaitBuckets` (`lt5,5-30,gt30`) — two wait vocabularies in one
  payload; they answer different questions, so name the second `waitMix` and say so.
* `report.php` writes `filterCallsByCallback($calls, $state, $links['returned'], …)` where
  `$links` is a `cdrCallbacks()` result, and 80 lines later reuses `$links` for the report block.
  Rename the first to `$callbacks` — same variable name, two meanings, in the file that defines
  what a "returned call" is.

## 3. What to build next

Ordered by (value ÷ effort), and deliberately constrained to data this app already loads
(`cdr_keep_fields.php` is 1,336 names; the CDR cache, `outcomes.php`, `links.php`, `capacity.php`
and the live `callqueue-*` fields) — "needs new data" is a separate list so nobody plans on
nothing.

### 3a. Cheap because the numbers already exist

1. **Callback worklist as a task, not a count.** Today "2 missed calls not returned" opens a
   table. Add: the number, the minutes since the miss, who last spoke to them, and a
   `not returned` export/snapshot per morning (`unreturnedList` is already built and truncated to
   `$top = 20` in `callLinkReport`). The next step is a *disposition* — returned today / out of
   scope / wrong number — which needs one small table (`callbacks(domain, missed_root, state,
   handled_by, at)`), the only new state the app would need.
2. **Recording-compliance exceptions.** `call-recording-status` is already kept. A per
   site/department report: answered calls with no recording available, recordings older than the
   retention, and "recording exists but was never played" — the audit trail already knows the
   second one (S1's `recording` audit rows).
3. **Finish the transfer analysis** (C4): queue→queue pairs, a **bounce rate** (calls handed back to
   the agent they came from, or ≥3 hand-offs — `cdrHopSequence` already orders the hops), and
   "transferred then abandoned" (handed to B, nobody answered) which `cdrTransferCount`
   deliberately excludes today and which is the number supervisors actually act on.
4. **Understaffed-interval report.** `pack.php` already computes the staffing number
   (`'offered x AHT / interval / occupancy'`, `pack.php:327-343`, with `capacity.php` guarding how
   much of the range fits in memory), and `queue.php` already has 15/30/60-minute SLA buckets
   (`intervalSla`). Put them together: the intervals where offered ÷ capacity > 1, ranked,
   with the abandon rate beside them — and, per C7, aligned to the *desk's* opening hours rather
   than the caller's.
5. **Caller-origin cut.** `normalizeCallNumber()`/`callCustomerNumber()` already reduce a number to
   digits; add area-code/country roll-ups to the DID screen (who calls us, from where, and what
   happens to them) — useful for a PH/US split, and it falls out of existing code.
6. **An "unanswerable" data-quality page** (the app already has all of it): per-day record counts,
   `complete` vs partial fetches, `cdrRangeCacheStatus`, days with zero rows, and — new — *schema
   drift*: the day a CDR arrives with fields not in `cdr_keep_fields.php`, or `callType()`
   classifies a growing share of rows as `unknown`, that is the leading edge of the class of bug
   this repo keeps fixing. One panel + one alert turns it into a 2-minute check instead of a
   week of "the numbers look wrong".
7. **Live wallboard.** `callqueue-count-agents-available/total` and
   `active-queued-calls-total-current` are live PBX fields already used by `queue.php`/`agents.php`
   KPIs; `alerts.php` already assembles thresholds. A 15-second-refresh, no-CDR-scan view (now
   waiting, longest wait, agents on, today-so-far vs target) is a new payload shape, not new data.
8. **A scheduled daily digest + a shared-link permission.** The report payload is
   `report.php`'s `data`; rendering it to HTML mail (or a CSV to an address) is a CLI over the same
   functions, like `tools/pbx-bench.php` is over the fetch path. `authorizedFilters()` already
   clamps spans by role, which is the same guard a link needs.
9. **Audit view for managers** (12 `auditView()` call sites write JSONL nobody reads): "who looked
   at which numbers, and exported what" — for a call centre holding caller PII this is a
   compliance feature, and after S1 the log should not be world-readable to be *read* by the right
   person.
10. **Saved views.** Filters already travel in the URL (`app-shell.js:36-48`) but only some keys;
    persist the whole `filters` object (`filtersKey` is exactly that list), add a named-save
    per user, and every card becomes a shareable link that shows what it says.

### 3b. New filters worth adding to the bar (all derivable from cached fields)

* **Duration bands** (0–30s / 30–60s / 1–5m / 5m+) — the *wait* bands exist in `summary()`
  (`waitBuckets`, `missedWaitBuckets`, `abandonWaitBuckets`); talk-time bands do not, and would be
  the same shape with `seconds($call,'call-talking-duration-seconds')` as the input; the DID screen
  already does exactly this for its own numbers (`telephone_numbers.php:498 'duration'`).
* **Disconnect cause family** — `call-disconnect-reason-text` is kept and shown per row; roll the
  strings into ~8 causes (`no-answer`, `busy`, `rejected`, `no-route`, `cancelled`, `normal`) and
  make cause a first-class filter and a breakdown card. This is where "why are we missing calls"
  actually lives, and it's the one big unused field in the payload.
* **IVR path** — `aa_options.php` already walks digits and the AA tree; "callers who pressed 1 then
  abandoned" is a filter over data that is already joined.
* **Recorded / not recorded**, **hold > 0**, **transferred ≥ 1**, **repeat caller within 72 h**
  (all four are one `isset`/comparison away in `callsRow()`/`filterCallsBy*`).
* **Was returned / is in the worklist today** — the callback states exist as a drill only; make
  them a bar filter (`filters.js`) and C1's class of bug gains a second test case for free.
* And whatever gets added must land in the `callFilters()` registry (C9) — a filter that exists in
  the bar but not in `calls.php` is C1 again.

### 3c. Needs new data — write it down as a question, don't plan a sprint on it

after-call-work time · wrap-up/disposition codes (why the caller called) · transfer *reason* ·
agent state/logins (available/paused — the PBX exposes queue-level `agents_available` but not
per-agent states in what this app caches) · outbound campaign linkage · live "who is waiting now"
per queue member. Each of these is a conversation with the PBX admin about a new endpoint, not a
report change; the app's pattern (`inventory.php` for rosters/queues, `aa_options.php` for trees)
shows how to add one when it exists.

## 3b. Housekeeping (small, but each one costs someone an afternoon of confusion)

* **H1** — `api/agents.php:44` `appLog('AGENTS DEBUG: cachedUsers count = ' . count($users));`
  runs on every Agents load. Delete (see C8).
* **H2** — `index.php` uses a relative include (S9).
* **H3** — `tests/js/harness.mjs`'s report fixture carries `summary.outcomes` and `summary.duration`,
  which `summary()` (`rows.php`) does not publish (the screens that *do* get those keys —
  `telephone_numbers.php:497-499`, `queue.php:778` — publish them under `charts`, and no component
  reads the report ones). Dead fixture weight is how a component looks tested while reading a key
  that never arrives; assert the fixture's key set against the endpoint's real response instead.
* **H4** — the tests' `callList()` helper passes `perPage: 100`; `calls.php` reads `size`
  (clamped 10..100) and ignores the rest — a fixture day with 26 rows would silently change what
  several assertions mean.
* **H5** — `filterCallsByWait`'s bands and `summary()`'s `waitBuckets` use the same
  `0-30/31-60/61-120/120+` strings, while `missedWaitBuckets`/`abandonWaitBuckets` use
  `lt5/5-30/gt30` in the same payload (see C10). Name the second pair `*WaitMix` and they stop
  looking like the first.
* **H6** — `report.php` reuses `$links` for two different things in one function (C10).
